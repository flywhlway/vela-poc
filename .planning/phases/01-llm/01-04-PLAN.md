  <action>
在 `OpenAICompatProvider` 上新增 `probe(self, physical_model: str) -> dict`（D-15 的探测原语）。它**不属于** `gateway/base.py::Provider` 抽象契约——契约不得扩展，`MockProvider` 也不需要实现它；Plan 06 的 doctor 用 `hasattr(provider, "probe")` 判定可探测性。

行为定义：
- 先 `try: self.ensure_credentials() except LLMError` → 直接返回 `{"reachable": False, "authenticated": False, "model_ok": False, "error_kind": "MissingCredentials", "detail": <异常消息>}`，**不发任何网络请求**。
- 否则发一次最小 chat：`self._client().chat.completions.create(model=physical_model, messages=[{"role": "user", "content": "ping"}], max_tokens=1, temperature=0)`。
- **归因表**（按 `isinstance` 逐条判定，顺序从具体到宽泛）：

  | SDK 异常 | reachable | authenticated | model_ok |
  |---|---|---|---|
  | 无异常（成功） | True | True | True |
  | `openai.APITimeoutError` / `openai.APIConnectionError` | False | False | False |
  | `openai.AuthenticationError` / `openai.PermissionDeniedError` | True | False | False |
  | `openai.NotFoundError` / `openai.BadRequestError` | True | True | False |
  | `openai.RateLimitError` | True | True | True |
  | `openai.InternalServerError` | True | True | False |
  | 其他 `openai.OpenAIError` | True | False | False |

  `APITimeoutError` 是 `APIConnectionError` 的子类，必须先判子类。`RateLimitError` 判为三项皆真的理由写进代码注释：限流意味着端点可达、鉴权通过、模型存在，只是配额受限；`detail` 中要明确标注「限流，未能完成最小调用」，避免被读成完全健康。`BadRequestError` 归到「模型不可用」是因为方舟对无效接入点 ID 常返 400 而非 404。
- 返回 dict 固定五键：`reachable` / `authenticated` / `model_ok` / `error_kind`（成功时为空串，否则为 `type(e).__name__`）/ `detail`（人读中文说明 + 截断到 300 字符的原始消息，**必须先过 `self._scrub()`**）。
- **安全约束（写进方法 docstring）**：`probe()` 不经 `LLMGateway.chat()`，因此不经 `gateway/redact.py` 脱敏。这是可接受的，且仅因为 prompt 是硬编码常量字符串 `"ping"`，不含任何用户数据、日志内容或证据文本。**任何后续改动都不得把可变内容传进 probe 的 messages**——这条禁令要以注释形式钉在构造 messages 的那一行上方。
