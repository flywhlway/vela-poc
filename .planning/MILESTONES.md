## v1.0 —— OTA 日志证据化诊断 POC ✓

**状态**：已交付（`pyproject.toml` version = 1.0.0）
**范围来源**：两份技术输入文档
- 《OTA 车端日志预处理与列式取证库技术方案》—— 数据层
- 《基于预算感知证据压缩与可追溯证据链的车联网海量日志智能诊断系统及方法》专利技术交底书 —— 推理层七大机制

**交付内容**：
- 七层管道架构：仿真/接入 → 证据平面（Stage-0~8）→ 查询平面（12 工具）→ 推理平面（七节点图）→ 模型网关 / 证据链平面 / 可观测与评估
- 约 7,100 行 Python（不含测试），61 个源文件，177 个单元/集成测试全绿
- 10 场景仿真数据集（9 故障 + 1 健康）+ 黄金评测集 + 6 项核心指标报表
- CLI 统一入口 + 本地 HTTP 服务（FastAPI 优先，stdlib 兜底）

**评测结果**：
- mock 供应商：Top-1 = 1.0，假阳性 = 0，悬空引用率 = 0.0
- **真实 LLM 首次接入实测：Top-1 = 44.4%**（9 个故障用例）

**遗留认知**（v1.1 的直接起因）：mock 的 100% 度量的是**闭集分类能力**而非开放域诊断能力。
后续四份代码级分析文档进一步揭示，仿真器、信号提取器、mock 打分器三者共享同一套格式约定，
形成自我确认的闭环——即 44.4% 这个数字本身也是在有利条件下取得的，且度量它的尺子（引用闸门）存在结构性盲区。
